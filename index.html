错题诊断器

作者：高一二班 张家铭

不是又一个错题本，
是一台「错因诊断 + 效果验证」的机器。

给高一学生在周测后整理错题时用，解决一件事：知道错了，但不知道错在哪一类，下次同类题照样错。

15分钟 手抄一道错题的平均耗时（访谈实测）
5人 已完成访谈的同学，其中 3 人根本不整理错题
0元 目前的开发与运行成本

01为谁解决什么问题

目标用户：高一学生本人。先自己用，再同桌，再本班，暂不考虑外班和初中。

典型场景：周测发下来，卷子上圈了五六个红叉。想整理，但手抄一道要十几分钟，抄到第三道就烦了，最后整个本子只写了两页。

这类场景里的三个真问题

  • 不是"找不到答案"，是"不知道错在哪一类" 答案和解析到处都有。真正缺的是有人告诉你：这道题你错在分类讨论漏了一种情况，而这类错你犯过四次了。
  • 整理的成本高到让人放弃 访谈中会整理错题的同学，单题平均耗时 15–20 分钟，且大多只在大考前才做一次。
  • 存下来的东西没人再看 一位同学的原话：「存了三十多道，一道没重做过。」存了不等于会了，但现在没有任何工具验证这件事。

02现在怎么解决，哪里不行

对比项 手抄错题本 市面错题 App 本项目
录入方式 手抄，15–20 分钟/题 拍照，秒级 拍照，秒级
分类粒度 自己随手写 粗知识点，如"三角函数" 知识点 + 错因双标签
能否看出薄弱点 翻本子自己数 有统计，但只到知识点 错因分布图 + 薄弱热力图
是否验证"后来会不会" 不会 基本不做 一周后出同型题，记录重做正确率
核心目标 把题抄下来 把题存起来、印出来 搞清楚为什么错、后来会不会

市面产品的定位并不差，只是它们把力气花在"存和印"，我们只做它们没做的那一段。

03我打算怎么做

四步，一条主线，没有分支。

  1. 1

    拍照上传

    对着错题拍一张，自动压缩到 200KB，8 秒内出结果。

  2. 2

    生成诊断卡

    题干、知识点、错因、置信度，四个字段结构化输出。

  3. 3

    错因归类

    按八类错因统计，画出个人薄弱热力图。

  4. 4

    一周后验证

    出同型题（只改数字），记录重做对错，算出真会率。

05我明确不做什么

这部分和"要做什么"同样重要。一个学期做不完所有事，砍掉什么比加上什么更能说明想清楚了。

拍照搜题出答案

2021 年后政策限制，且题库是数十亿题级别的护城河，个人无法竞争。

自建题库

需要数月积累，一学期做不完，还涉及版权。

擦除手写笔迹

图像处理重活，是成熟产品的核心投入，做了也没有差异化。

导出 PDF 组卷打印

市面产品已免费提供，不是本项目的价值所在，留待有余力再说。

它是怎么做出来的（技术说明）
  • 页面本身是单个 HTML 文件，纯 CSS 绘制，无框架、无外部图片、无 CDN 依赖，加载快且不会因为图片失效变空白。
  • 托管在 GitHub Pages，与代码同仓，改完提交即更新。
  • 正式版将由静态前端 + 一个 Serverless 函数组成，函数负责隐藏 API Key 并转发请求。
  • 识别环节使用多模态大模型，提示词约束它只做归类、不解题，并强制返回固定 JSON 结构；知识点必须从预设枚举表中选，避免分类发散。
  • 数据先存在浏览器本地，后续迁移到云端数据库，图片不外传第三方图床。
  • 表单由 formsubmit.co 转发到邮箱，无需自建后端。
